# 20 · `kd ai` — memória de agentes

## Para que serve

Consulta, **read-only**, a memória de um **agente** guardada em shards NDJSON dentro do projeto:
`.knudge/ai/<área>/<agent_id>.jsonl`. Cada linha é uma nota no schema do knudge
(`{"frontmatter": {…}, "body": "…"}`), e cada escritor tem o seu próprio ficheiro. É a porta para o
knudge ser o **eixo único de memória**: qualquer agente que escreva esse formato passa a ser
consultável pelo `kd`, sem código novo e sem o knudge aprender o formato interno de ninguém.

| Área | O que lê | Default |
|---|---|---|
| `memory` (default) | a **memória** do agente | `.knudge/ai/memory/` |
| `session-log` | a **projeção** do log de sessão em notas derivadas (`activity=derive`) | `.knudge/ai/session-log/` |

Cada diretório contém **um shard por `agent_id`** — o agente principal e cada subagente escrevem no
seu ficheiro. O knudge varre os `*.jsonl` de primeiro nível do diretório (não recursivo); não há
manifesto nem ficheiro de índice da fonte. `events/` está reservado e não é lido.

O log de sessão **não** entra como domínio novo: quem o projeta é o **agente** (uma nota derivada
por afirmação, com `provenance.activity=derive`); o knudge só a indexa. O log continua a ser do
agente — uma só verdade.

## Quando usar

- **Use** quando o agente guarda a memória em shards NDJSON e você quer pesquisá-la com o motor do
  knudge (BM25 + âncoras + grafo + RRF).
- **Use `kd ai session-log`** para responder "o que fizemos sobre X?" **entre** sessões, por
  significado, em vez de reler logs.
- **Use `kd ask --agent`, `--activity`, `--agent-id` ou `--agent-role`** quando a memória **já**
  está em `notas/` e só quer filtrar por **quem** produziu cada nota.
- **Não use** para escrever na memória do agente: o `kd ai` é read-only. Gravar é do agente
  (contrato abaixo).

## Sintaxe

```
kd ai [AREA] [QUERY...] [--source PATH] [--limit N] [--sort id|time]
      [--agent-id ID...] [--agent-role main|subagent ...] [--params JSON|-]
```

| Flag/posicional | Contrato |
|---|---|
| `AREA` | `memory` (default) ou `session-log`; valor fora do conjunto ⇒ exit `2` com a lista |
| `QUERY...` | consulta textual; **sem** query, **lista** a fonte (`id\|tipo\|statement`) |
| `--source PATH` | fonte explícita: **ficheiro** NDJSON ou **diretório** de shards; default `.knudge/ai/<área>/` |
| `--limit N` | limite do recall (default: `recall.default_limit` da config) |
| `--sort id\|time` | ordem da lista; no recall, `time` reordena os hits já limitados (default `id`) |
| `--agent-id ID` | filtro por instância (`provenance.agent_id`); repetível ou vírgula |
| `--agent-role PAPEL` | filtro por papel (`main`/`subagent`); repetível ou vírgula |
| `--params JSON\|-` | objeto JSON que define a consulta inteira; `-` lê de stdin |

Com `--params`, o objeto substitui os argumentos: aceita `query` (string ou lista), `area`,
`source`, `limit`, `sort`, `agent_id` e `agent_role`. Como no `ask` (D147), não há merge com as
flags da linha de comando.

## Exemplos

```bash
# 1. o que há na memória dos agentes?
kd ai

# 2. buscar na memória (todos os shards do diretório)
kd ai memory "rate limit do gateway"

# 3. buscar na projeção do log de sessão
kd ai session-log "por que trocamos o modelo de embedding"

# 4. só o que um subagente registou, em ordem temporal
kd ai memory --agent-role subagent --sort time "parser TOON"

# 5. várias instâncias (vírgula ou repetição)
kd ai memory --agent-id omp-main,omp-sub-1 "dedup"

# 6. uma fonte fora da convenção (ficheiro ou diretório)
kd ai memory --source /tmp/shards "parser TOON"
kd ai memory --source /tmp/export.jsonl "parser TOON"

# 7. enxuto, para um agente ler
kd ai memory "dedup" --limit 3 --json

# 8. a consulta inteira via JSON (stdin)
printf '%s' '{"area":"memory","query":"dedup","limit":3,"sort":"time","agent_role":["main"]}' \
  | kd ai --params -
```

## Saída

- **Lista** (sem query): `id|tipo|statement`, um por linha.
- **Recall** (com query): `id|statement|score`, um por linha; sem hits ⇒ `[no_results]`.
- **`--json`**: envelope padrão (`success`, `command`, `data`; `warnings[]` só quando há avisos).
  O payload em `data` é `{area, source, sort, query, data}`: `data.notes[]` na lista e
  `data.hits[]` no recall; ambos trazem `created_at`, `agent`, `agent_id`, `agent_role` e
  `parent_agent_id` (`null` quando ausente). `source` é o caminho resolvido da fonte (no default,
  `<raiz>/.knudge/ai/<área>`).

```json
{
  "success": true,
  "command": "ai",
  "data": {
    "area": "memory",
    "source": "/projeto/.knudge/ai/memory",
    "sort": "id",
    "query": "",
    "data": {
      "notes": [
        {
          "id": "fact_0a1b2c3d",
          "type": "fact",
          "statement": "O gateway limita a 100 rps por chave",
          "created_at": 1761700000000,
          "agent": "omp",
          "agent_id": "omp-main",
          "agent_role": "main",
          "parent_agent_id": null
        }
      ]
    }
  }
}
```

```json
{
  "success": true,
  "command": "ai",
  "data": {
    "area": "memory",
    "source": "/projeto/.knudge/ai/memory",
    "sort": "id",

    "data": {
      "hits": [
        {

          "agent_role": "main",
          "parent_agent_id": null
        }
      ]
    }
  }
}
```

## Ordem

- **`--sort id`** (default): `id` ascendente — ordem determinística histórica.
- **`--sort time`**: `(created_at, agent_id, id)` ascendente (D222).
- No **recall**, o default é **score**; `--sort time` reordena apenas os hits que já caberam no
  `--limit`.

## Filtros de identidade

`--agent-id` e `--agent-role` comparam por igualdade com `provenance.agent_id` e
`provenance.agent_role`. São listas de seleção como as restantes (repetição ou vírgula).

- Na **lista**, aplicam-se os defaults de leitura: sem `agent_id` vale `provenance.agent` e, na
  falta dele, `legacy`; sem `agent_role` vale `main`.
- No **recall**, os filtros usam os metadados do índice com os **mesmos defaults de leitura**
  (`agent`→`agent_id`, ausente→`main`), pelo que uma nota v2 é filtrável como na lista.
- Uma nota de outro produtor mas já em `notas/` é filtrável no `ask`:
  `kd ask --agent ktu "…"`, `kd ask --activity derive "…"`, `kd ask --agent-id omp-main "…"` ou
  `kd ask --agent-role subagent "…"`.

## Como um agente integra

O agente é o **dono** da memória; o knudge só lê. O contrato do escritor:

1. **Um shard por `agent_id`.** Grave em
   `.knudge/ai/<área>/<agent_id>.jsonl` — nunca num ficheiro compartilhado no caminho quente.
   `agent_id` deve casar com `provenance.agent_id`.
2. **Append de uma linha JSON completa + `\n` por evento.** Abra o shard em modo **`O_APPEND`** e
   faça uma única escrita por evento; nunca reescreva nem trunque o ficheiro.
3. **`created_at` monotónico em milissegundos**, por agente. É o eixo temporal e o critério de
   desempate entre shards.
4. **Identidade em `provenance`:** `agent` (nome lógico), `agent_id` (instância), `agent_role`
   (`main`/`subagent`) e, em subagente, `parent_agent_id`. `agent_id` **não** entra no `id` da nota
   (o id continua content-addressed).
5. **`fsync` em batch é opcional.** Sem fsync, um crash pode perder os últimos eventos; a leitura
   nunca depende dele.
6. **Sem lock de leitura.** O knudge varre os shards enquanto o agente escreve; cada linha é
   completa e uma linha parcial no fim é ignorada com warning naquela leitura.

### Linha de exemplo

```json
{"frontmatter":{"id":"fact_0a1b2c3d","type":"fact","statement":"O gateway limita a 100 rps por chave","created_at":1761700000000,"body_hash":"1a2b3c4d","schema_version":3,"tags":["gateway"],"anchors":[{"path":"src/gateway.rs"}],"provenance":{"activity":"write","agent":"omp","agent_id":"omp-main","agent_role":"main"}},"body":"Medido no gateway de produção."}
```

A linha acima é uma única linha JSON terminada por `\n`; repita-a por evento.

### Nome do shard

`shard_file_name(agent_id)` é seguro e determinístico:

| `agent_id` | Shard |
|---|---|
| `omp-main` (só `[A-Za-z0-9._-]`, ≤ 96, ≠ `.`/`..`) | `omp-main.jsonl` |
| `omp main/1` (inseguro) | `omp-main-1-5381c52b.jsonl` |

No caso inseguro, os caracteres proibidos viram `-`, o prefixo é truncado a 48 caracteres (ou vira
`agent` se ficar vazio) e `hex8` são os 4 primeiros bytes do SHA-256 do id **original**, em
hexadecimal — o hash preserva a identidade e evita colisões.

### Projeção do log

Se o agente tiver um log cru, **projete-o** em notas derivadas (`provenance.activity=derive`) num
shard de `session-log/` e aponte o `kd ai session-log` ao diretório — nunca ingira o log como nota
canónica.

## O que esperar

- **Fonte ausente** ⇒ lista vazia e exit `0` (não é erro: o agente pode ainda não ter memória).
- **Linha malformada** ⇒ ignorada com um **aviso** em `stderr` que nomeia o shard e a linha; em
  `--json` o aviso vai em `warnings[]`.
- **Ficheiro ilegível ou não-UTF-8** ⇒ aviso e fonte ignorada, sem derrubar a leitura.
- **Mesmo `id` em dois shards** ⇒ vence o maior `(created_at, agent_id, caminho do shard)`; dentro
  do mesmo shard vence a última linha.
- A ordem da lista é **determinística** (`id` ou tempo), então a mesma fonte dá sempre o mesmo
  resultado.
- **Sem caminho legado:** fontes fora de `.knudge/ai/` exigem `--source` explícito; não há
  descoberta automática de outros diretórios.
